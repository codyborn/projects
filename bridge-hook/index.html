Proof of concept

Cross-chain hops as routable edges

A Uniswap v4 hook that wraps Across, so the router can price and path through a bridge the same way it prices any other pool.

Today a cross-chain route is swap, bridge, swap, stitched together by an orchestrator. The bridge is a system the router calls.

Here the bridge is a pool. The cross-chain hop becomes one more edge in the graph, so Uniroute and GuideStar can optimise across it with the pathfinding that already exists.

The intent, encoded at source

// hookData on the v4 swap
BridgeIntent {
  destinationChainId: 130,      // Unichain
  recipient:          RouteContinuation,
  outputToken:        WETH,
  fillDeadlineOffset: 1800,
  message:            Continuation {
    target:         UniversalRouter,
    callData:       swap(WETH → UNI),
    finalRecipient: user
  }
}

Why this is priceable

Across fieldWhy it matters
outputAmountSet by the caller, not an oracle. The hook states the output it will accept, so the leg is simulatable on-chain with no API call.
messageArbitrary calldata run on arrival. The onward route travels with the intent.
outputTokenMay differ from the input, so bridge and swap collapse into one intent.

Known gaps, stated plainly

  • The source leg quotes zero output. The output exists on another chain, which is honest accounting but means amountOutMinimum is meaningless here. Production wants a claim token so the leg has a real quoted output and somewhere to hold a refund. This is what Hop's hToken is.
  • The fee is a constant. Real deployments should read Across suggested-fees rather than a fixed basis-point cut.
  • No refund path on the source side. If no relayer fills before fillDeadline, Across refunds the depositor, which is the hook. The hook has no logic to return those funds to the user.
  • Custom accounting needs trace-based simulation. Events report a swap value of zero, so routing must simulate rather than read events.
  • Not audited, never deployed. The destination half is unit tested; the hook has not been exercised against a live PoolManager.
Hook calls a deployed Across SpokePool. Across contracts are BUSL-1.1, which restricts copying, not calling; only the function signature is reproduced, and the destination handler interface is MIT. Built for the Uniswap Fall Onsite hackathon.
